# ParamIntel v0.6 AI Advisor Observability

The AI Candidate Advisor is a hypothesis source, not an evidence source. This observability slice makes that boundary measurable in both verbose CLI output and JSON reports.

## Candidate lifecycle

Each provider suggestion now retains a bounded audit record with:

1. provider-suggested name, placement, priority, and reason;
2. deterministic local admission decision;
3. local rejection reason when rejected;
4. whether the candidate entered ParamIntel discovery testing;
5. whether ParamIntel independently verified it;
6. candidate/control trial counts and deterministic confidence for verified results.

The report uses these outcomes:

- `locally_rejected` — model output failed deterministic local admission and was never tested;
- `not_verified` — candidate was admitted into discovery testing but did not become a ParamIntel finding;
- `verified` — candidate survived ParamIntel verification and carries `ai_semantic_hypothesis` provenance.

## Local rejection reasons

Current deterministic rejection reason codes are:

- `invalid_name`
- `inactive_location`
- `invalid_json_parent`
- `already_present`
- `duplicate`
- `candidate_budget_exhausted`

These are local decisions. The model cannot override them.

## Meaning of `tested`

For this v0.6 slice, `tested=true` means the AI candidate was admitted as an exact seed into ParamIntel's normal discovery screening path. It does not mean the model verified the candidate, and it does not imply a finding.

`verified=true` is stricter: a matching ParamIntel result must exist and that result must retain the `ai_semantic_hypothesis` candidate source. A generic finding with the same name or placement is not credited to AI.

## Confidence boundary

AI priority and rationale never contribute to ParamIntel confidence. Verified audit records copy the confidence and candidate/control counts from the normal deterministic finding only after discovery completes.

## Acceptance example

The localhost `labs/v0.6-ai-advisor` acceptance established the intended A/B behavior:

- AI disabled: the normal built-in candidate path produced zero findings;
- AI enabled: Gemini proposed `include_archived`;
- ParamIntel independently verified `include_archived` with 3/3 candidate changes and 0/3 paired random-name control changes;
- confidence was 1.00 HIGH.

The audit layer now makes the other model suggestions visible as admitted-but-not-verified or locally rejected rather than silently discarding that information.
