# ParamIntel v0.8 — Controlled JSON Scaffolding

ParamIntel v0.8 extends deterministic context-response intelligence to a narrow class of nested JSON candidates whose immediate parent object is absent from the captured request.

The release goal is **deeper structured JSON discovery without generic JSON tree invention**.

## Problem

Before v0.8, a related response could reveal a candidate such as:

```json
{
  "profile": {
    "name": "tobias",
    "settings": {
      "beta_access": false
    }
  }
}
```

while the captured request contained only:

```json
{
  "profile": {
    "name": "tobias"
  }
}
```

ParamIntel could identify `$.profile.settings.beta_access` structurally, but it could not test that leaf because `$.profile.settings` did not exist in the request.

v0.8 introduces an explicit, conservative scaffolding path for this case.

## Release rule

> ParamIntel may create exactly one missing JSON object level only for a deterministic response-derived candidate, only when its direct ancestor already exists as a request object, and only when the user explicitly enables `-json-scaffold` together with `-context-response`.

The verifier remains authoritative. Scaffolding is candidate placement, not evidence.

## Classification

Context intelligence now distinguishes:

- **Actionable** candidates — the JSON parent already exists in the request;
- **Scaffoldable** candidates — the immediate parent is absent, but its direct ancestor exists as an object;
- **Skipped** candidates — deeper missing structure or incompatible request structure prevents safe one-level scaffolding.

A scaffoldable candidate records:

- exact JSON leaf path;
- missing immediate parent path;
- response-derived provenance;
- observed response type;
- a lower contextual priority than immediately actionable candidates.

Classification itself does not authorize network mutation.

## Independent authorization layers

Controlled scaffolding requires all of these conditions:

1. deterministic context-response classification marked the candidate scaffoldable;
2. `-json-scaffold` is enabled;
3. `-context-response` is supplied;
4. discovery configuration admits scaffold candidates;
5. each active mutation carries explicit scaffold authorization;
6. the mutator independently verifies that exactly one final object component is absent and its direct parent already exists as an object.

Candidate metadata alone cannot make the mutator create an object.

## Candidate/control symmetry

For a candidate:

```json
{
  "profile": {
    "settings": {
      "beta_access": "probe"
    }
  }
}
```

the paired random-name control uses the same scaffold and probe value:

```json
{
  "profile": {
    "settings": {
      "zz_pi_random": "probe"
    }
  }
}
```

Only the leaf name changes.

This preserves ParamIntel's central experiment:

> Does this specific parameter name produce reproducible behavior that a random unknown name at the same placement does not?

If merely creating `settings` or placing any child inside it changes behavior, the random control reproduces the signal and the candidate is rejected.

## Probe isolation

Scaffold candidates are placed in one-candidate initial groups. They are not bulk-batched with ordinary wordlist or contextual candidates.

This keeps the first v0.8 implementation attributable and bounded:

- one scaffold hypothesis per initial group;
- one missing object level;
- normal repeated candidate/control verification afterward.

## Explicit CLI opt-in

Use:

```text
-context-response response.json
-json-scaffold
```

`-json-scaffold` without `-context-response` fails locally before target probing.

Scaffolding is disabled by default.

## Deliberate exclusions

v0.8 does **not**:

- synthesize two or more missing object levels;
- traverse or mutate arrays as scaffold targets;
- replace an existing object, `null`, scalar, or array with a new object;
- invent missing parent names from the generic wordlist;
- let the AI Candidate Advisor invent missing parent paths;
- copy response primitive values into attack/probe values;
- change candidate/control confidence scoring;
- reinterpret different candidate/control evidence signatures when both sides change;
- automatically exploit a discovered mass-assignment condition.

Strict-schema false negatives remain preferable to weakening the paired control model in this release.

## Interaction with AI Candidate Advisor

`-json-scaffold` does not expand AI authority.

AI candidates continue to pass the existing local admission model and do not receive scaffold metadata. Only deterministic `-context-response` classification can produce scaffoldable candidates in v0.8.

## Interaction with value-aware discovery and characterization

All discovery-side active mutations are constructed through the same scaffold authorization helper. Therefore:

- generic verification;
- paired random controls;
- value-aware semantic rescue;
- characterization

all follow the same scaffold gate when operating on an admitted scaffold candidate.

## Existing safety and evidence integrity remain in force

v0.8 does not bypass:

- `-allow-state-changing` for POST/PUT/PATCH/DELETE and other potentially state-changing methods;
- global `-delay` request pacing;
- known 429 / explicit 503 backoff fail-closed handling;
- multi-request baseline stability;
- v0.7 stable-feature evidence rules;
- paired random-name controls;
- confidence thresholds.

A known limiter/backoff response still cannot become discovery evidence.

## Acceptance coverage

Automated tests and `labs/v0.8-json-scaffolding` prove:

1. a response-derived nested field can be confirmed when exactly one parent object is missing;
2. the candidate changes while its paired random-name control remains baseline-like;
3. generic behavior caused by any child under the new parent is rejected when the control reproduces it;
4. disabling scaffolding prevents scaffold candidates from being sent;
5. existing `null`, scalar, array, or object parents are never replaced through the scaffold path;
6. paths requiring two missing object levels are rejected;
7. scaffold metadata must match the candidate parent;
8. scaffold candidates are isolated from bulk discovery groups;
9. the real CLI path works with `-context-response`, `-json-scaffold`, and the state-changing-method safety gate.
