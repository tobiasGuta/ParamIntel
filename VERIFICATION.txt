Independent pre-merge review hardening:
- removed the fixed a1b2c3d4 token fallback
- probe/control tokens now use 8 random bytes (16 hexadecimal characters)
- token generation fails closed and propagates an error when secure entropy is unavailable
- regression coverage injects a failing entropy reader and requires an explicit error
- confidence scoring is documented as a deterministic evidence-ranking heuristic, not a calibrated probability or significance estimate
- README surfaces default -locations auto behavior near the introduction

Key v0.3 regression/integration coverage:
- a related raw HTTP response can be parsed for a JSON object body
- a bare JSON body can be used directly as context
- request-versus-response structural comparison excludes properties already present in the request
- response string values are never tokenized into candidate names
- response-only root properties become exact JSON candidates when the root request object is available
- response-only nested properties become exact JSON candidates only when their parent request object already exists
- nested response fields with missing request parents are observed but deliberately not made actionable
- contextual candidate ordering is deterministic
- contextual candidates are tested in first-pass groups before generic dictionary candidates
- a generic duplicate cannot erase contextual candidate provenance
- findings retain context source path, observed JSON type, and priority
- mass-assignment-style acceptance test discovers $.chosen_discount from response context even though chosen_discount is absent from the supplied generic wordlist
- the contextual candidate still passes the standard verifier: repeated candidate behavior, paired random-name controls, and confidence scoring are unchanged

Preserved v0.2 coverage:
- GraphQL-style hidden query discovery
- form-body parameter discovery
- root and nested JSON discovery
- JSON-shaped request bodies under non-JSON MIME types such as text/plain
- negative-control rejection for generic unknown-parameter behavior
- conservative type inference and typed value profiling
- arrays remain excluded from JSON insertion semantics

External validation conclusion:
- v0.3 can learn a real application-specific field from a related API response without receiving that field from a wordlist, then independently verify it with the existing negative-control model.
- merely appearing in a context response is not sufficient for a finding; a synthetic response-only field was considered as a candidate but rejected by behavioral discovery/verification.
- the real contextual workflow and its negative-control boundary are both validated externally.

Scope boundary:
- v0.3 does not scrape arbitrary response words, synthesize missing JSON object scaffolding, traverse arrays for insertion, add Burp/MCP/AI integrations, or change the core verifier/scoring model.
