ParamIntel v0.5.0 verification
Date: 2026-08-28
Status: automated implementation acceptance PASS; external Windows CLI acceptance PENDING

Release goal
------------
v0.5 protects ParamIntel's evidence model from responses that are known to represent rate limiting or explicit server backoff, and adds optional global request-start pacing without changing the discovery algorithms or confidence model.

Core invariant:
- a response known to be rate-limited/backoff must never become a model.Snapshot used by compare.AgainstBaseline

Implementation status
---------------------
Slice 1 — typed backoff classification: COMPLETE
- HTTP 429 always becomes a typed rate_limit BackoffError
- HTTP 503 becomes server_backoff only with a valid Retry-After
- Retry-After integer seconds supported
- Retry-After HTTP-date supported
- malformed Retry-After on 429 is retained as raw metadata but is not trusted as parsed timing
- ordinary 503 remains an ordinary response
- ordinary 403 remains an ordinary response
- classified responses are rejected before Snapshot construction
- rejected response bodies are still closed
- baseline construction aborts immediately if any sample is classified as backoff
- errors.As can recover BackoffError through wrapped baseline errors

Slice 2 — global request-start pacing: COMPLETE
- added -delay duration flag
- default -delay 0 preserves previous unpaced behavior
- negative delay rejected before network activity
- pacing implemented once at the shared HTTP transport
- the same paced client is used by baseline construction and the discovery engine
- spacing is measured between request starts, not as unconditional post-response sleep
- context cancellation interrupts a pacing wait
- pacing state is race-safe
- zero delay returns the underlying transport unchanged

Slice 3 — discovery-phase evidence integrity: COMPLETE
- group probe 429 aborts scan; no narrowing decision is made from limiter behavior
- candidate probe 429 aborts verification before control is sent
- random-name control 429 invalidates the paired experiment; no partial confidence/trial result is returned
- value-aware candidate screen 429 aborts rescue with no finding
- value-aware same-value control 429 aborts rescue with no finding
- semantic request budget still counts requests that were actually sent before the 429
- characterization 429 after a valid discovery aborts the scan rather than returning a partially characterized normal result
- real CLI subprocess regression proves rate-limit abort exits non-zero and does not create the requested findings file

Slice 4 — release hardening: IN PROGRESS
- CLI version bumped to ParamIntel v0.5.0
- release version is pinned by an automated test
- README updated for the v0.5 evidence-integrity model
- CHANGELOG updated for v0.5.0
- reproducible Windows acceptance lab added under labs/v0.5-rate-limit
- external acceptance results are intentionally not marked PASS until run on Windows

Backoff classification acceptance
---------------------------------
Automated tests prove:

1. 429 never becomes a Snapshot.
2. BackoffError is discoverable through errors.As.
3. Retry-After seconds parse correctly.
4. Retry-After HTTP-date parses correctly.
5. malformed Retry-After on 429 does not panic and remains raw metadata.
6. 503 + valid Retry-After becomes server_backoff.
7. 503 without Retry-After remains an ordinary response.
8. 503 + malformed Retry-After remains an ordinary response.
9. 403 remains an ordinary response.
10. rejected 429 response bodies are closed.
11. a baseline that receives 429 fails immediately and does not accept remaining samples.

Discovery integrity acceptance
------------------------------
Automated tests prove:

- group probe -> 429
  result: Scan returns BackoffError and no normal results

- candidate -> 429
  result: control is not sent and no confidence/trials are returned

- candidate -> normal behavioral change; random control -> 429
  result: pair is invalid, scan errors, no partial confidence is produced

- value-aware screen -> 429
  result: rescue errors, no result/value is returned, one actually-sent request is charged to semantic budget

- value-aware candidate screen -> meaningful; same-value control -> 429
  result: rescue errors, no finding, two actually-sent requests are charged to semantic budget

- confirmed candidate -> characterization -> 429
  result: Scan aborts and does not return a normal partially characterized result

Known boundaries
----------------
v0.5 deliberately does not add:
- automatic retries after 429/503
- automatic sleeping/resume from Retry-After
- adaptive concurrency
- rate-limit/WAF inference from arbitrary 403 pages or body text
- cache-aware probe correlation
- server-side parameter-pollution mutation inside another parameter value
- missing-parent JSON scaffolding synthesis
- array insertion
- AI-generated semantic values
- Burp/MCP integration
- broad business-state enum spraying

ParamIntel findings remain research leads requiring manual authorization, impact, and exploitability validation.
