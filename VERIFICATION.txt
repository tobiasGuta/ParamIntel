ParamIntel v0.11.0 release verification
Date: 2026-09-21
Status: RELEASE HARDENING — implementation and external acceptance complete; final branch CI required before merge/tag

Release goal
------------
v0.11 improves how ParamIntel allocates a bounded semantic-rescue request budget while preserving the existing evidence boundary.

Core rule:
- AI, OpenAPI, context structure, and scheduler priority may decide what is worth testing.
- Only live application behavior, repeated trials, paired random-name controls, and the existing confidence model may produce a finding.

Release scope
-------------
1. Evidence-guided rescue ordering
   - deterministic evidence tiers
   - candidate-source priority
   - local contextual relevance
   - lower deterministic screening cost
   - stable fallback order

2. Rescue request accounting
   - per-candidate evidence tier and reason
   - source priority and contextual relevance
   - deterministic value count
   - actual AI provider-query status
   - admitted AI values
   - budget before/after
   - requests used
   - outcome
   - discovery mode for verified findings
   - top-level used/verified/miss/exhausted request accounting

3. Verification-feasibility floor
   - with three trials, a new semantic value is not started when fewer than 8 requests remain
   - the floor reserves candidate screen + paired control + complete repeated verification
   - unused tail requests are reported as verification_budget_insufficient rather than ordinary exhaustion

4. Compatibility hardening
   - body-less OpenAPI operations may contribute operation and response-schema intelligence
   - no JSON request body or writable response-only candidate is invented for body-less operations
   - AI semantic-value audit distinguishes actual provider calls from advisor availability

Trust boundary
--------------
Unchanged:
- mutation semantics
- paired negative controls
- repeated verification
- confidence calculation
- finding admission
- rate-limit/backoff fail-closed behavior
- state-changing-method authorization
- OpenAPI and AI remain hypothesis/provenance inputs, not confidence evidence

Release boundary
----------------
v0.11 is feature-frozen.

Do not add for this release:
- reinforcement-learning scheduling
- provider-confidence scoring
- aggressive semantic-profile truncation
- automatic vulnerability judgment
- looser confidence thresholds
- weaker negative controls
- autonomous exploitation

Any new capability belongs in a later version unless release hardening exposes a correctness, safety, or compatibility defect.
